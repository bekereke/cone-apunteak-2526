# MikroTik Basic Firewall Configuration

> _What do we actually achieve with this configuration?_\
> In practice, this configuration turns your router into a "fortress." Without a firewall, every device on the internet can see and attempt to interact with your router.

#### 1. Invisible Mode (Stealth)

By using a `drop` rule on the `WAN` interface, your router stops responding to random scans. To an attacker, your router appears to be "off" or non-existent, preventing brute-force attacks on your Winbox or SSH ports.

#### 2. Stateful Inspection

The router tracks the _state_ of connections.

* Outgoing: If a student opens a website, the router remembers that request (Established).
* Incoming: The router only allows traffic from the internet if it is a response to a student's internal request. Unsolicited traffic from the outside is blocked.

#### 3. Performance Optimization (FastTrack)

By skipping firewall checks for packets that are part of an already trusted, established connection, the router saves significant CPU resources, allowing for higher throughput (more Mbps).

#### 4. Management Security

By limiting `input` access to the `LAN` list, you ensure that only people physically connected to your internal network can configure the router.

<summary>Chains</summary>

A chain is essentially a "path" that a packet takes through the router. To understand which chain to use, you must ask one question: **Where is the packet's final destination?**

#### 1. The INPUT Chain

Destination: The Router itself.

* What it is: Traffic sent _to_ one of the router's own IP addresses.
* Examples: \* A student trying to log into the router via Winbox or SSH.
  * A Ping sent to the router’s gateway IP (`192.168.10.1`).
  * DNS requests sent from a PC to the router.
* Security Goal: To protect the "brain" of the router from unauthorized access or attacks.

#### 2. The FORWARD Chain

Destination: Another device (Beyond the router).

* What it is: Traffic that enters one interface and exits another. The router acts only as a "middleman" or "postman."
* Examples: \* A PC in the LAN browsing Google (traffic goes through the router to the WAN).
  * A device in the LAN talking to the DB Server on a different subnet.
* Security Goal: To control what users in your network can access and to prevent outsiders from reaching your internal servers.

#### 3. The OUTPUT Chain

Destination: Outside the router, but originating _from_ the router.

* What it is: Traffic generated by the router's own operating system (RouterOS).
* Examples: \* The router checking for System Updates.
  * The router sending a Ping from its own terminal to a website to test the connection.
* Security Goal: Rarely used in basic setups, but can be used to prevent a compromised router from communicating with a "command and control" server.

#### **Summary of Firewall Chains**

| ChainText | Packet Source   | Packet Destination       | Typical ActionText                         |
| --------- | --------------- | ------------------------ | ------------------------------------------ |
| INPUT     | Anywhere        | The Router               | Allow Admin / Drop Everyone else.          |
| FORWARD   | Internal Device | Internet (or vice-versa) | Allow Browsing / Drop Unauthorized access. |
| OUTPUT    | The Router      | Anywhere                 | Usually Accept all.                        |

### Step-by-Step Graphical Configuration (Winbox)

How to configure the Firewall using the GUI.

1. Open the Firewall Window: Navigate to `IP -> Firewall` and stay on the Filter Rules tab.
2. Create "Input" Rules (**To protect the Router**):
   * Rule 1 (**Accept Established/Related**): Click `+`. Chain: `input`. Connection State: Check `established` and `related`. Action: `accept`.\
     ![](<../../../.gitbook/assets/irudia (9).png>)![](<../../../.gitbook/assets/irudia (10).png>)
   * Rule 2 (**Accept LAN Management**): Click `+`. Chain: `input`. In. Interface List: `LAN`. Action: `accept`.
   * Rule 3 (**Drop Everything Else from WAN**): Click `+`. Chain: `input`. In. Interface List: `WAN`. Action: `drop`.
3. Create "Forward" Rules (**To protect the Internal Clients**):
   * Rule 4 ([**FastTrack**](mikrotik-basic-firewall-configuration.md#id-3.-performance-optimization-fasttrack)): Click `+`. Chain: `forward`. Connection State: `established`, `related`. Action: `fasttrack connection`.
   * Rule 5 (**Accept Established/Related**): Click `+`. Chain: `forward`. Connection State: `established`, `related`. Action: `accept`.
   * Rule 6 (**Drop Unauthorized WAN traffic**): Click `+`. Chain: `forward`. In. Interface List: `WAN`. Connection NAT State: Check the box for `NOT` and select `dstnat`. Action: `drop`.\
     ![](<../../../.gitbook/assets/irudia (8).png>)
4. Check all the rules look alike:\
   ![](<../../../.gitbook/assets/irudia (21).png>)

{% hint style="danger" %}
**Remember that the order of the rules matters:** \
Rules are processed from top to bottom. Always place your "Accept" rules at the top and your "Drop" rules at the bottom.
{% endhint %}

{% hint style="warning" %}
Let's proof that the firewall is running okay:\
-**Disable rules:** Put their computer on the WAN network and ping your router's public IP (`192.168.69.201`). You'll get an answer.\
&#xNAN;**-Enabled rules:** Activate the drop all from WAN rule. Now the ping will fail.\
-**Winbox test:** Try to access Winbox through that public IP. The firewall will deny him access, but the student connected from the LAN cable will continue to manage it smoothly.
{% endhint %}

### Address Lists

To apply rules to a group (or single) by IP:&#x20;

#### Step 1: Create the Address List

1. Go to `IP -> Firewall`.
2. Click on the Address Lists tab (usually the third or fourth tab).
3. Click the `+` (Add) button.
4. Name: Type a descriptive name (e.g., `Restricted_Servers`).
5. Address: Type the IP address (e.g., `192.168.10.50`).
6. Click OK.

{% hint style="info" %}
To add multiple IPs to the same list, simply repeat the process but use the exact same Name. MikroTik will group them together automatically. You can even add a range (e.g., `192.168.10.50-192.168.10.60`) or a whole subnet (`192.168.10.0/24`).
{% endhint %}

#### Step 2: Use the Address List in a Filter Rule

Now that the list is created, you need to tell the Firewall to block everything inside that list.

1. Go to the Filter Rules tab and click `+`.
2. General Tab:
   * Chain: `forward`
   * Out. Interface List: `WAN`
3. Advanced Tab (This is the key step):
   * Look for Src. Address List.
   * Select your list name (`Restricted_Servers`) from the dropdown menu.
4. Action Tab:
   * Action: `drop`
5. Click OK and move the rule to the top.

<summary>(ALL ABOVE) Step-by-step Script Configuration (CLI)</summary>

This script provides a baseline security level for a standard SOHO (Small Office/Home Office) setup.

```bash
# --- 1. PROTECT THE ROUTER (INPUT CHAIN) ---
# Allow traffic that we started ourselves
/ip firewall filter add chain=input action=accept connection-state=established,related comment="Allow established/related"

# Drop packets that make no sense (security)
/ip firewall filter add chain=input action=drop connection-state=invalid comment="Drop invalid"

# Allow Ping (ICMP) for testing
/ip firewall filter add chain=input action=accept protocol=icmp comment="Allow Ping"

# Allow Winbox/Management ONLY from the LAN
/ip firewall filter add chain=input action=accept in-interface-list=LAN comment="Allow LAN management"

# Block everything else coming from the Internet
/ip firewall filter add chain=input action=drop in-interface-list=WAN comment="Drop all other WAN input"

# --- 2. PROTECT THE CLIENTS (FORWARD CHAIN) ---
# FastTrack established connections for maximum speed
/ip firewall filter add chain=forward action=fasttrack-connection connection-state=established,related comment="FastTrack"

# Allow traffic for established sessions
/ip firewall filter add chain=forward action=accept connection-state=established,related

# Drop everything else from WAN that isn't specifically allowed (Port Forwarding)
/ip firewall filter add chain=forward action=drop connection-state=new connection-nat-state=!dstnat in-interface-list=WAN comment="Drop unauthorized WAN-to-LAN"
```

Address Lists

```bash
# Group the IPs
/ip firewall address-list add address=192.168.10.50 list=Restricted_Servers
/ip firewall address-list add address=192.168.10.51 list=Restricted_Servers
# Create One Rule to Rule Them All
/ip firewall filter add chain=forward action=drop src-address-list=Restricted_Server
```
